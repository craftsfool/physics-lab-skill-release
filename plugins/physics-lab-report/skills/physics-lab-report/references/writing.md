# 模块内容与文风

先按 [栏目要求与验收](template-requirements.md) 拆解用户实际模板。以下模块表是写作参考，不代替括号内的逐项要求。

## 按所需模块写

| 模块 | 必须保留 |
|---|---|
| 实验名称 | 与课程一致的名称，不凭编号猜实验。 |
| 目的 | 2—4条具体目标，通常为观察/验证、仪器方法、数据分析。 |
| 原理 | 简述机制、原理图/光路或电路、主要公式、量定义及适用条件。 |
| 方案及仪器 | 仪器名称；连接和测量对象；关键调节。型号和精度无依据时不猜。 |
| 步骤/操作要点 | 可执行顺序和影响精度的条件；不要抄满教材步骤。 |
| 过程及现象 | 操作—观测；另列问题—处理。反映本人记录，不把“通常现象”写成实测。 |
| 数据记录 | 原始单位、分组、表号、零点与量程记录；原始数据只改确认的误读。 |
| 数据处理及结果 | 公式、换算、代表性代入、关键拟合/结果、理论比较、物理结论、附图图号。 |
| 总结讨论 | 按实际模板覆盖收获、反思及指定思考题解答；结合规律、数据证据、误差及改进，结论强度不超过证据。 |
| 思考题 | 先结论，再物理解释，最后结合实验；未知题干不补造。 |
| 应用拓展 | 聚焦实际应用或用户专业相关研究，说明应用场景、工作机制及研究问题；用户为计算机专业时优先结合计算机领域。不与本实验对比，不回顾本实验原理、数据或结果；不把假设项目写成已经实现。 |

## 过程中的问题与处理

整份实验后报告必须显式覆盖这一项，但只能写有记录的实际问题；不要生成“接线接错”“仪器故障”“光强剧烈波动”等没有依据的故事。

- 实验操作中确有异常：说明观察、原因判断、执行的处理及处理后的现象。
- 从记录能证实的数据整理问题：可以说明复测组选择、角度定义核对和订正，但不能冒充仪器问题。
- 实验结果偏离理想规律：先描述偏差，再写已完成的分析；复查零位、增加重复测量等尚未执行的措施写为建议。
- 没有任何问题记录且这一栏必填时，只询问该缺口；其余模块继续。通用注意事项可列为操作要点，不能写成“已经遇到并解决”。

## 正文和工作说明分开

正文用短段落，表格只用于并列、比较或操作/问题对应；适合直接抄写。压缩时保留核心，不堆套话，不伪造“成功验证”“误差较小”。预习没有数据时写理论预期，不提前写实验成功。

打印区清除任务回答、修改历史、缓存说明、程序运行提示、个人确认过程和AI措辞。保留科学性说明，例如“该量程未记录，未计算合成不确定度”“理论曲线仅按功率尺度归一化”。页眉、图题和图例同样检查，禁用“最新样式”“PPT example”“required”“抄写内容”等任务标签。

用户需要手写稿和打印附页时分开给：手写稿依据同模板前人书写密度规划，正文保留充分的解释、关键计算和结论；小原理图、短表格、并排公式可与文字共同排列，不由电脑版段落空白反推篇幅。打印附页含表格/图及正式图注。不要在最终报告里插入面向用户的“你可以”“建议抄到”等句子。

## 参照内容先完整，再做选择

默认参照PDF提供超过预计手写空间的有依据内容，允许多页；主要依据为教材，前人报告不决定知识取舍。建立要点与输出位置清单，原理、处理、总结各承担不同作用，不重复整段叙述，也不漏掉主要公式、关键计算、条件和指定题目。仅用户要求时另做手写精简稿。含公式的PDF先用LaTeX编译并查看实际渲染，具体见 [参照PDF与公式](latex-and-reference.md)。
