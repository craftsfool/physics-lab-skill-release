# 共用首次引导

安装 Setup 和报告技能首次调用都走本页。先按技能所在目录解析脚本的绝对路径；不要在用户目录中猜测同名脚本。命令中的路径是占位示例。

## 介绍与状态

运行 `python3 <报告技能>/scripts/onboarding.py status`，只读，不创建目录。未完成介绍时，先向用户展示 [使用指南](usage-guide.md) 的亮点、完整六步流程及适用的平台说明，然后运行 `onboarding.py introduced` 记录已介绍。不能只给链接或只输出环境检测结果，也不能未展示就写完成状态。

用户明确要求“使用指南”时无论状态如何都完整介绍；“重新设置”时运行 `onboarding.py reset`，再走首次流程，不触碰私密配置、报告、原始材料或旧技能。不要因每个新聊天、新实验或小版本更新重复完整介绍。

脚本默认使用当前用户配置目录，`--state-file <路径>` 可指向宿主允许的持久状态位置；状态仅保存介绍时间和 `device/api/local/none` 来源选择，不保存端点或令牌。无 Python 或持久文件能力时，使用当前会话已有记录并说明不能跨会话保存，继续可完成的工作；不声称状态已持久化。文件损坏时报告问题，不把损坏当作来源授权。

## 检测与来源选择

优先提供无需第三方登录的 [设备登记](device-and-chapters.md)：首次登记30天 Key，可查询摘要和按权限在线预览教材章节。来源选择包含设备登记、已有API令牌、本地资料、无参考资料。检测到设备配置文件时用 Node 客户端 `status` 检查是否完成登记与到期；不能仅凭文件存在声称已接入。已登记设备来源沿用，无需重新登记。缺 Node 或持久存储时提供已有令牌/本地资料路线。

介绍之后按 [环境](environment.md) 检查 API、编译器和计算工具。之前选择了本地/无参考资料时分别沿用 `local` / `none`；用户明确提供本地材料时也可沿用该授权。目录中碰巧有材料不等于用户已经选择。

无来源选择且缺少 API 配置时，询问：“你希望登记设备领取30天资料 Key、配置已有API令牌，还是使用本地资料（也可不提供参考资料继续）？”已有有效配置时沿用 API，无需再问；用户明确选定后用 `onboarding.py choose-source --reference-mode device|api|local|none` 记录。

选择 API 但配置未完成时，保留选择并说明待配置，通过宿主私密配置设置环境变量，不能要求把令牌发到聊天中，也不将令牌传给本脚本。仅在配置成功后按需验证一个模块。API 报错时按环境页询问修复或换来源，不自动切换；先前授权的回退方案可直接沿用。

选择本地后才运行环境脚本的 `--local-materials` 创建资料目录。选择 `none` 时记录无参考资料，不创建空文件夹。状态中的来源选择只决定资料路线，不代表授权扫描用户未指定的目录。

确认检测能力后，简短说明本次可用的预览、编译和计算工具，询问影响当前任务的必要缺失信息并直接继续。只有写作任务时不静默安装 LaTeX 或其他依赖。
