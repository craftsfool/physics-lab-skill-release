# 报告预览与定点修改

## 桌面端

首先检查当前宿主实际提供的文件打开、工程创建、编译及选区/批注能力，不虚构工具或按钮。有 `create_latex_project` / `open_in_codex` 时，新报告创建在独立工程中并打开工程；已有工程在原位编辑，保持原来的预览入口。宿主内置编译器可用时保存源文件后由编辑器自动编译刷新，Agent 修改后再用 `compile_latex_document` 验证。编译调用返回 busy/stale 时短暂等待后有限重试，不因预览暂未刷新就另建同名报告。

工具不存在时使用宿主等价能力；仅缺内置编译器时按环境页使用现有本地编译器。没有预览能力时说明当前支持文件交付与逐轮修改。插件不注入自有编辑界面，不保证每个预览都具备选区/框选或批注，也不模拟没有拿到的选区。

## 选区如何落到源文件

1. 读取宿主传入的批注、源文件路径/行号、引用文字、页码及栏目；确认它对应用户当前报告，不是参考教材。没有选区上下文时请求引用原文或指定栏目。
2. 重新读取当前源文件。LaTeX 源文件是当前编辑依据；不要从旧内容 JSON 重新生成整份报告覆盖用户手改。先查找引用文字，再结合栏目、页码、布局清单定位；PDF 渲染文本不能直接作为 LaTeX 字符串替换。
3. 仅当目标唯一时执行修改。用当前文件字节的 SHA256 和待替换的原始 LaTeX 生成 JSON：`source_sha256`、`old_text`、`new_text`；重复内容时增加 1-based、含首尾的 `start_line` / `end_line`。这些是源文件行号，不是 PDF 行号。运行 `python3 <技能>/scripts/edit_report.py <report.tex> --edit <edit.json> --dry-run`，通过后去掉 `--dry-run` 应用。
4. 哈希不一致、原文不存在、范围内有多个匹配时停止该替换，重新定位。不能用全局替换、近似匹配、第一处命中或整栏重写猜测选区。工具不提供任意指令执行；编辑内容只能来自已确认的报告修改。
5. 修改前判断关联影响：纯措辞修改保留其他内容；数值、单位、公式模型变化时同步必要的表格、计算、图和引用，并向用户说明这些更新。未提供的原始数据不因“改好看”而改动。

脚本只校验并应用文本范围，不判断物理正确性，也不会自动编译。多处修改按每次最新源文件重新定位与计算哈希。目录和源文件须处于用户授权的报告工程中；临时 edit JSON 只能包含报告编辑内容，禁止写入完整资料 API 响应或凭据。

## 编译、导出与失败

应用后保存同一份源文件，验证编译并查看实际版面。失败时保留用户编辑和最后成功 PDF，明确“预览是上一份成功版本，当前修改尚未编译成功”，修复当前源文件，不将失败源文本冒充成品。

内置预览可能尚未导出磁盘 PDF。交付时必须从当前源文件重新实际编译/导出；有 XeLaTeX 时可运行 `scripts/compile_report.py <report.tex>`。其两轮编译和越界检查通过才替换磁盘 PDF；检查文件版本、页数、上下标、表格与图例。内置编译、磁盘 PDF、人工版面检查分别记录真实结果。

## 网页端及无编辑器环境

使用用户上传或本次生成的源文件，以栏目、页码和引用文字定位；在当前环境有编译能力时交付新 PDF 与源文件。没有编译器时交付可编辑源文件并说明 PDF 待编译，不声称实时预览。引用不唯一时请用户补充位置。不要建立远程服务或上传原始记录来绕过环境限制。
